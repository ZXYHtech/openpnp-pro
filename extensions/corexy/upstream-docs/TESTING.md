# 正式回归测试

## 自动检查

每次准备发布时必须完成：

1. 执行 `tools/build.ps1`，Java 单元与集成测试必须全部通过。
2. 使用 OpenPnP 相同方式，把所有 `.py` 和 `.pytxt` 读取为 UTF-8 Unicode 后执行 `compile(..., "exec")`。
3. 检查脚本首行不存在 Python 编码声明。OpenPnP 以 Unicode 字符串编译脚本，编码声明会触发 `encoding declaration in Unicode string`。
4. 逐一比较项目脚本和 `.openpnp2/scripts` 中已部署副本的 SHA-256。
5. 记录构建 JAR、现场已测试 JAR 和正式配置的 SHA-256；冻结过程不得改写正式配置。

## 中文主流程

1. 机器处于 Disable、未 Home，点击“开始新标定”。
2. 确认原生 X/Y backlash 已设为 `None`，新 Session 建立且进入未补偿基线模式。
3. Enable、Home，完成未补偿 Primary 固定网格采集。
4. 生成固定向量候选，确认自动跳转到“候选与应用”。
5. 检查推荐值自动填入、默认补偿比例 100%、A/B 数值保留 3 位小数。
6. 点击“应用补偿”，确认等待静止、自动 Disable、A/B 状态清空及编辑控件锁定。
7. 重新 Enable、Home，分别运行空载往返检查和健康检查。
8. 确认健康报告生成、残差右侧两图刷新、状态页下一步与实际机器状态一致。
9. 再次运行健康检查，确认允许重复检查且不会要求重新建立 Session。
10. 点击“停用补偿”，确认自动 Disable、推荐值重新填入且编辑控件解锁。
11. 修改补偿比例后再次应用，确认显示值、正式配置和状态页一致。
12. 重启 OpenPnP，确认正式补偿和 UI 语言分别持久化。

## English 主流程

切换到 English，至少复测以下界面和动作：

- 页签、按钮、状态、下一步提示和使用说明。
- 新标定、应用、停用、健康检查的确认及完成弹窗。
- 测量进度窗口、取消/停止动作和错误提示。
- 报告继续使用中英并列字段，数据键、路径、Session ID、PASS/WARNING/FAIL 不翻译。

## 判定与安全

- 应用/停用时不得有生产任务运行。
- 每次应用或停用后都必须重新 Enable 和 Home。
- 健康检查结束后机器自动 Disable；重复检查前也要重新 Enable 和 Home。
- 健康 PASS 只说明方向状态残差满足像素门限，不表示所有绝对落点进入 0.05 mm 圈。
- 自动结果与用户生产验收分开记录；FAIL 不会自动停用补偿。
- 发现异常运动、软限位错误、坐标漂移或 Home 不一致时立即停止并停用补偿。

## 发布记录要求

正式发布的 `TEST_RECORD.md` 至少记录：测试日期、OpenPnP 版本、自动测试数量、脚本编译数量、中文/英文人工回归结论、最近匹配当前正式配置的健康检查状态以及所有未覆盖项。
