# OpenPnP Pro 2.6P2 更新日志

OpenPnP Pro 的版本号基于原版 OpenPnP 版本追加 `P` 和单数字迭代号。本版本基于 OpenPnP 2.6，首个 Pro 迭代版本定义为 **2.6P1**。

## 2.6P2 本轮更新
### 悬浮监控交互、任务预测与安全暂停

- 悬浮监控改为独立工具窗口并保持工具包级模态排除，避免部分 Windows 10/JRE 环境中被主程序对话框阻塞后无法拖动或点击。
- 对话框桥接由“只同步错误”扩展为同步错误、警告、确认和自定义选项；复位贴片状态等操作会在悬浮窗显示相同按钮，任一窗口处理后另一边同步结束。
- 悬浮警告不再被重复错误通知覆盖；窗口会自动恢复可用、可聚焦和置顶状态。
- 悬浮相机改为镜像主界面相机的最终呈现状态，复用识别结果图、动态准星、底部视觉附加框、封装框和文字，不再启动一条缺少附加层的独立显示流。
- 最近任务按时间顺序合并“连续相同任务”，累计展示全部耗时、单板、器件、异常与平均速度，同时保留每次运行明细和每条异常所属任务信息。
- 增加历史学习与实时节拍融合的预计总耗时、预计完成时间、预测准确度、样本置信度和预测偏差。
- 记录送料、取料、底部视觉对位、贴装、任务准备和收尾等阶段耗时，结合结构化异常源分析拖慢原因。
- 改善建议可指出反复故障的具体飞达、重复底部视觉对位、拾取偏移迹象、暂停过久和显著超过历史基线的阶段。
- “吸嘴清空后暂停”在所有吸嘴本来就没有物料时，立即进入与普通暂停相同的 `Pausing → Paused` 状态，不再只设置一个无反馈请求。
- 复位全部贴片状态增加确认步骤，并由主界面与悬浮窗共享同一个确认结果。
### 3D 安全工作台与飞拍轨迹放行

- 安全包络升级为多贴装头动态模型：为 N1、N2 等每支吸嘴分别保存机头本体、吸嘴杆、收起/伸出 Z 标定点和外露长度，吸嘴包络随实时 Z 插值变化。
- 当前机头移动 XY 时，同头其他吸嘴同步平移但保持独立 Z；其他贴装头保持自己的位置并作为动态障碍物，不同机头包络相交会拒绝轨迹。
- 吸嘴携带元件后，自动读取 Part 封装宽深和元件安全高度，扩大横向及下方碰撞包络。
- 3D 物体升级为可辨认的实物化示意：飞达带料轨与料盘、相机镜头、PCB 焊盘和走线、散料盘格位、贴装头/吸嘴及半透明禁入区。
- 增加编辑/实时运行双模式、当前贴装头跟随、窗口置顶、运动轨迹尾迹和实时 FPS；位置读取不会插入额外 G-code 或完成等待。
- “实验功能”新增“3D 安全工作台”，提供可旋转、缩放的等距 3D 视图；可从物体库拖入飞达、贴装头、底部相机、散料飞达、电路板、禁入区和自定义物体。
- 物体支持方体、圆柱和 XY 自定义轮廓；可编辑原点、三轴尺寸、安全间隙，并为底部相机单独定义中央通道。
- 支持读取当前工具头位置记录物体原点、最小/最大角点和多边形轮廓点；工具头采点只读取位置，不会自行移动机器。
- 新增工作台最小/最大安全位置、工具头三维安全包络和轨迹采样间距设置。
- 碰撞检查覆盖整条线段和工具头扫掠体，不只检查起终点；可发现斜向 XYZ 联动中途撞入飞达、相机边框或工作台边界的情况。
- 提供安全 Z 分段、XYZ 联动直线、联合下降—定高飞拍—联合抬升三种动态预演；轨迹按安全状态显示绿色或红色。
- 引入修订认证机制：任何物体拖动、尺寸、轮廓、工作台边界或工具包络修改都会使旧认证立即失效并锁住真机实验。
- 真机联合运动还要求实验模式、机器启用并回零、吸嘴无料、软限位可达、整段碰撞检查通过、现场安全勾选和最终人工确认。
- 正式实验飞拍现在要求当前 3D 模型已认证，并检查抬升、横移、下降、定高经过和再次抬升的完整轨迹；采集完成或异常时进入安全 Z 回撤流程。
- 模型保存在配置目录 `pro-safety-workbench.json`；详细说明见 `OPENPNP_PRO_3D_SAFETY_WORKBENCH_CN.md`。

### 实验性飞拍底部视觉

- “实验功能”新增“飞拍视觉中心”，提供类似首次引导的动态分步说明、静止连拍基线、低速经过相机、多次重复统计和 CSV 导出。
- 复用相机连续采集接口和现有 Bottom Vision Pipeline；新增预采集帧通道，不改变普通停拍时原有的开灯、稳定和抓图逻辑。
- 多帧按清晰度、Pipeline 成功、中心时刻和轨迹位置综合选帧；记录每帧采集时刻，并扣除估算的吸嘴轨迹位移。
- 可配置相机延迟用于估算曝光时刻；普通 USB 相机没有可靠硬件时间戳时默认关闭，并限制飞拍速度不超过机器最大速度的 35%。
- 正式任务采用实验模式、功能开关、正式接入开关和 Part ID 白名单四重门控；未在白名单中的元件完全沿用普通 Bottom Vision。
- 无帧、图像模糊、Pipeline 失败、偏移或角度超限时可自动回退普通停拍；目前仅支持后旋转 Bottom Vision。
- 物理测试必须在机器启用、完成回零、吸嘴携带测试元件且操作者确认路径无障碍后才可执行；所有移动先经过 Safe Z 和可达性检查。
- 飞拍调试图片及报告保存于配置目录下的 `pro-flying-vision` 文件夹；详细说明见 `OPENPNP_PRO_FLYING_VISION_CN.md`。
### 实验模式与运动性能补偿中心

- “窗口”菜单新增“实验模式”，默认关闭；启用后才显示仍在验证中的实验功能，避免生产操作员误触。
- 首个实验功能为“运动性能与补偿中心”，使用八步动态可视化引导完成安全预检、异步驱动、运动基线、共振降噪、回差精度、分级参数和结果应用。
- 支持识别当前 Gcode 驱动，并可一键升级为 `GcodeAsyncDriver` 或回退为普通驱动；转换前自动备份 `machine.xml`，机器启用时禁止替换。
- 修复原有 Gcode 驱动序列化转换未真正替换类型的问题；回退时恢复升级前的超时尺度，避免反复转换造成超时不断放大。
- 校准中心直接显示 X/Y/Z/C 各轴速度、加速度、Jerk 与回差参数，先给出建议，再由用户确认应用，不在后台偷偷修改机器参数。
- 增加受控短程运动测试：要求机器已启用、已回零、吸嘴无料且工作区无障碍；先抬到 Safe Z，再在当前位置附近执行可达性检查后的低速短行程，并显示总耗时和平均分段耗时。
- 动态示意图同步表现龙门轨迹、振动衰减、回差方向与速度曲线；“一键可视化预检”可自动播放整套流程，不会自动驱动真实机器。

### Win10 升级安装与悬浮错误交互修复

- Windows 安装版本提升为 2.6.2，旧版 Pro 可被识别并正常升级，避免重复使用 2.6.1 导致安装界面不出现或不覆盖。
- 保持固定升级标识，升级只替换 Pro 程序文件，不替换原版 OpenPnP，也不分离飞达、吸嘴等共享机器数据。
- 错误弹窗在显示前即与悬浮监控绑定，消除“悬浮窗先收到错误、原弹窗后出现”造成的失联。
- 悬浮窗使用工具包级模态排除，主界面出现模态错误时仍可点击悬浮窗。
- 在悬浮窗确认错误会同步关闭对应的主界面错误框；在主界面处理错误也会同步清除悬浮警告，不再要求两边各点一次。

## 2.6P1 历史更新

### 兼容深色主题与低饱和启动界面

- 新增“兼容深色（Windows 7 / 10）”，由软件完整控制菜单、表格、输入框、弹窗、滚动区域及标题栏配色，不依赖 Windows 系统深色模式。
- 兼容主题使用软件自绘深色窗口装饰，重新启动软件后标题栏也保持深色。
- 强调色改为低饱和灰蓝，减少高亮色面积，提高旧显示器和工业现场长时间使用的舒适度。
- 启动页面改为石墨灰渐变和低饱和装饰，不再使用鲜艳蓝绿背景。
### 悬浮监控快捷功能扩展

- 悬浮窗底部按钮由固定 4 个扩展为可配置 4–8 个。
- 自定义功能库扩展到 50 多项，按任务、对位、机器、点动、页面、编辑和窗口分类。
- 必须包含并可直接选择“吸嘴贴完暂停”：继续完成所有吸嘴现有物料的贴装，确认吸嘴全部为空后安全暂停。
- 增加单步、停止、取料、延后错误、封装检查、Mark 对位、抛料、回收、各轴点动、停靠、主要页面切换及撤销重做等入口。
- 所有生产动作复用主界面原始 Action，不绕过原有启用状态和机器安全限制。
### 安装、共享机器数据与安全备份

- 原版 OpenPnP 与 OpenPnP Pro 使用不同的程序名称、安装目录和应用标识，可同时安装，升级 Pro 不会替代原版程序。
- 两个程序共同使用 `.openpnp2` 中唯一的一套机器生产数据，飞达、吸嘴、相机、物料和封装不会分叉为两套配置。
- 为避免争用机器或同时写入共享配置，Pro 启动时检测其他 OpenPnP 进程；发现冲突后只允许重新检测或退出，不提供强制关闭和带冲突继续运行。
- Pro 首次接入已有 `.openpnp2` 时会先完成强制全量备份，用户确认备份位置后才进入软件；用户任务文件本体不进入备份。
- “窗口 → 备份与恢复中心”支持按类别和具体文件选择，显示文件功能、大小和数据项数；覆盖机器、飞达、吸嘴、物料、封装、视觉、脚本、单板、拼版、最近任务关联，以及快捷键、表格宽度和悬浮监控等界面偏好。
- 恢复前自动保存当前对应文件的保护副本，恢复完成后提示正常重启。
- 首次使用引导改为直接覆盖真实软件界面的聚光导览，不再使用脱离界面的说明窗口。
- 导览增加 9 个分步主题，并在切换步骤时自动定位左侧导航、顶部任务栏、任务、元件库、看板和底部状态区。
- 每一步增加矢量图示和轻量动画，快捷键步骤直观展示“按住 Ctrl + 鼠标左键单击按钮”的操作过程。
- 桌面悬浮监控独立为一个完整步骤，介绍前台自动收起、边缘停靠、悬停展开、按钮配置和错误联动。
- 导览正文改为自动换行的可滚动区域，修复右侧长文字被截断或显示不完整。
- 主窗口标题、左侧品牌区及“关于”窗口统一显示版本 **2.6P1**。
- “关于”窗口增加“Pro 更新日志”页签，帮助菜单增加“Pro 更新日志”入口。
- 新增“吸嘴清空后暂停”：请求后继续贴完所有吸嘴上的物料，所有吸嘴为空时才安全暂停；贴片板列表和顶部快捷栏提供同步的纯图标按钮，再次点击可取消。

# OpenPnP Pro 界面与贴片效率优化说明

更新时间：2026-07-27

## 一、改版目标

本次改版围绕“减少页面切换、降低重复点击、提高物料管理一致性、强化异常恢复和机器动作安全”展开。界面不只调整颜色和间距，也重新组织了高频操作入口，并为后续自动巡检与 AI 视觉辅助建立扩展基础。

## 二、界面与操作效率

### 1. 现代化主界面

- 重构主窗口的信息层级、顶部命令区、工作区标题和状态提示。
- 统一面板背景、间距、圆角按钮、强调色和危险操作视觉状态。
- 保留 OpenPnP 原有业务结构，避免仅为视觉效果破坏成熟工作流。

### 2. 顶部快捷任务栏

- 菜单和控制面板中由 `Action` 驱动的按钮可固定到顶部。
- 固定项会保存到本机偏好设置，下次启动自动恢复。
- 固定按钮复用原始动作，因此启用状态、图标和机器安全限制保持同步。
- 最多直接显示 8 项，更多项目自动收纳到“More”菜单。
- 顶部固定项支持右键或中键快速移除。

### 3. 自定义快捷键

- 按住 Ctrl 点击菜单或按钮即可进入快捷键设置。
- 快捷键按动作永久保存，并在启动后重新加载。
- 冲突时进行提示，避免同一组合键同时触发多个动作。

### 4. 表格交互

- 主要业务表格关闭自动挤压列宽，列边界更容易抓取和拖动。
- 任务、飞达和贴装列表支持多选。
- 多选后修改一个可编辑单元格并按回车，可将同列值批量应用到选中行。
- 适用于优先级、启用状态以及其他允许批量修改的字段。
- 表头和表体的列边界使用灰色细实线，宽表格中更容易定位属性列及拖拽边界。

### 5. 左侧导航折叠

- 左侧工作区导航增加折叠/展开按钮。
- 折叠后只保留图标和当前选中状态，为任务表格释放更多横向空间。
- 鼠标停留在折叠图标上仍可查看菜单名称。
- 折叠状态保存到本机偏好设置，下次启动自动恢复。
- 折叠按钮位于 OPENPNP PRO 软件名称块下方靠侧边位置。

### 6. 自动调整列宽

- 主要列表表头右上角增加 `↔` 自动宽度按钮。
- 双击普通表头可按当前页面可见宽度重新分配全部列宽。
- 双击列边界可只按内容调整目标列，单列最大不超过页面宽度的 65%。
- 有数据行时只采样最多 200 行内容，不把属性栏标题宽度计入自动宽度；空表时才按属性栏标题调整。
- 分配顺序按自然宽度从小到大，状态、数值和短 ID 等窄列优先满足。
- 采样内容自然宽度超过 260 像素的长文字列按完整显示宽度的 50% 设置，并最后分配空间，避免挤压关键操作列。
- 长文字列不参与剩余空间扩展；普通列满足自然宽度后再均匀吸收页面余量。
- 被截断的单元格悬停显示完整内容，属性栏悬停显示完整属性名称。
- 贴装器件列表默认按 Rank 升序显示；可多选器件后按住鼠标右键拖动，以蓝色插入线确定新位置。
- 拖动完成后自动重写 Rank 并保存实际执行优先顺序；曾按其他属性排序时，拖动会自动切回手动 Rank 顺序。
- 普通右键点击仍打开原有操作菜单，只有按住并移动后才触发排序。

## 三、任务与飞达

### 1. 当前任务飞达高亮

- 载入任务后自动分析启用单板中的有效贴装项。
- 当前任务会使用的飞达以绿色区分。
- 任务需要但飞达未启用时以警告色显示。
- 未被当前任务使用的飞达保持普通状态。
- 任务切换后自动刷新，不需要手动重新筛选。

### 2. 更少的页面往返

- 高频机器、任务和自定义动作可直接固定到顶部。
- 顶部直接展开特殊功能选项和工具头选择栏，不再需要打开下拉菜单。
- 特殊功能名称超过 4 个字符时显示前 4 个字符和省略号，悬停显示完整名称。
- 操作员可以直接切换吸嘴、相机或执行器，无需展开控制面板。

## 四、物料、型号与封装

### 1. 物料数据模型

- 保留原 `Part.id` 作为永久唯一的内部 ID。
- 增加允许重复的显示物料 ID `displayId`。
- 增加内部型号或工艺变体 `variant`。
- 增加客户料号、ERP 编码、旧料号等别名 `aliases`。
- 两个不同内部物料可以显示相同业务物料 ID，同时分别保留高度、封装、速度和视觉配置。

### 2. 封装数据模型

- 增加标准封装名称 `standardName`。
- 增加封装别名 `aliases`。
- 新字段均为可选字段，旧配置文件和旧任务不需要重建。

### 3. 输入检索式选择

- 用可输入、可提示的检索方式替代超长物料下拉列表。
- 支持按显示 ID、内部 ID、型号、别名、名称、封装 ID、封装说明和封装别名搜索。
- 已接入任务贴装、单板贴装、拼板定义和通用飞达配置入口。

## 五、封装对位检查

- 在任务工具栏增加“Package Alignment Check”。
- 必须先选择单板并配置有效原点。
- 离线状态也能打开全板器件查看器。
- 在线移动前检查机器是否启用、是否已经回零以及相机是否可用。
- 机器未回零时仅显示器件，不执行移动。
- 移动前由操作员确认，并通过 Safe Z 将顶相机移动到单板原点。
- 检查动作不拾取、不下压吸嘴，也不修改 Placement 完成状态。

## 六、底部视觉异常恢复

当底部视觉对位失败时，不再只显示单一错误退出框，而是提供：

- 抛料并重新拾取；
- 原位重新执行视觉检测；
- 保持任务暂停；
- 终止任务；
- 查看完整错误详情。

“抛料并重新拾取”不是简单地重新执行当前视觉步骤：系统会先安全抛料，将失败贴装项恢复为 Pending，在后续周期重新规划和拾取；其他吸嘴和已完成贴装项不会被重复处理。

## 十、退出可靠性修复

根据实际运行日志，退出流程会重复记录“Shutting down”，但停在机器或相机关闭阶段，无法到达完成状态。现已调整为：

- 退出请求只处理一次，避免连续点击重复进入关闭流程。
- 配置保存和未保存任务确认仍在硬件关闭之前完成。
- 界面确认结束后立即隐藏，不再让操作员误以为按钮没有生效。
- 禁用机器与关闭机器转入后台执行，各自设置 3 秒超时。
- 单个相机、驱动器或硬件线程无响应时记录警告并继续退出。
- 最终保证 Java 进程结束，不再无限等待硬件释放。
## 十一、启动、取料与自动恢复

### 1. 启动速度与进度页

- 增加深色渐变的 OPENPNP PRO 启动页，显示真实初始化阶段和百分比，不再长时间停留在无反馈状态。
- 进度覆盖运行环境、主题、工作区、机器配置、工具头同步、快捷操作和自动恢复等阶段。
- 脚本菜单扫描与 Startup 脚本延后到主窗口首次绘制之后执行，优先让主界面可见、可响应。
- 配置加载失败或首次欢迎对话框出现前自动关闭启动页，避免启动页遮挡需要操作的窗口。

### 2. 顶部安全取料

- 顶部命令栏增加“取料”按钮，直接使用飞达页面当前选中的单个飞达。
- 当前工具必须是吸嘴；未选择有效飞达、飞达未配置物料时给出明确提示。
- 若吸嘴配置了物料检测传感器，以传感器结果判断是否占用；未配置传感器时使用吸嘴当前物料状态。
- 吸嘴为空时直接执行原有完整取料流程；检测到物料时先询问是否抛料，确认后安全抛料再取料。
- 取料仍复用飞达准备、兼容吸嘴头检查、校准、Safe Z、真空检查和脚本回调等现有安全步骤。

### 3. 贴装任务右键菜单

- “启用”“禁用”“已贴片”“未贴片”移动到右键菜单首层，适配单选和多选操作。
- “编辑对应飞达”放在高频状态操作之后，可快速定位器件供料配置。
- 器件类型、板面和异常处理保留为分组子菜单，降低首层菜单拥挤程度。

### 4. 工具头双向同步

- 修复顶部工具头选择框创建期间尚未绑定控件实例、首次刷新被跳过的问题。
- 机器配置加载完成后强制刷新工具头列表并同步当前吸嘴、相机或执行器。
- 顶部选择和右下角机器控制选择保持双向联动，启动后不再默认空白。

### 5. 临时自动保存与恢复

- 每 2 分钟在机器空闲时执行一次低优先级后台恢复快照；机器正在运动或执行任务时自动跳过。
- 快照写入系统临时目录下的 `OpenPnP-Pro-Autosave`，不覆盖正式配置、任务、单板或拼版文件。
- 保存机器配置、物料、封装、视觉与脚本状态、当前任务，以及所有已载入的单板和拼版文件。
- `recovery-info.txt` 记录恢复文件与原始路径的对应关系，未正式保存的新任务也会写入 `current-job.xml`。
- 最多保留最近 6 代快照，旧快照仅在专用自动保存目录内清理。
- 自动保存不会修改正式文件路径，不会清除未保存标记，也不会弹出保存确认框。
## 十二、物料匹配与桌面悬浮监控

### 12.1 物料输入匹配稳定性

- 修复表格内物料搜索输入时，自动匹配事件被误认为“编辑完成”，导致输入框刚显示便自动退出的问题。
- 输入过程持续显示候选项；仅在按下回车、Tab、确认选择或真正离开单元格时提交。
- Esc 可取消本次修改，避免误选物料。

### 12.2 桌面实时摄像头悬浮窗

- 第一次启动默认开启，可在“窗口 → 悬浮监控设置”中打开或关闭。
- 独立显示主界面当前活跃摄像头；主界面没有单独选择摄像头时自动使用第一路可用摄像头。
- 默认宽度为当前屏幕的五分之一，并提供右下角拖拽缩放、标题栏拖动和位置/尺寸记忆。
- 支持标题栏最小化；“停靠”后自动藏入最近的左右屏幕边缘，鼠标悬停展开，离开后重新收起。
- 默认底部按钮为“启动、停止、取料、停靠”；设置中可分别替换为回零、机器电源或隐藏等操作。
- “取料”复用顶部工具栏的安全取料逻辑，保留吸嘴有料检测和抛料确认。
- 机器或任务错误出现时，已最小化或贴边的悬浮窗会强制展开，并在摄像头画面中央显示醒目警告；确认后可关闭警告层。
- 软件退出时主动停止额外的摄像头监听和定时器，避免残留后台窗口或阻碍退出。
### 12.3 第二轮兼容性整改

- 彻底取消物料搜索对 Swing 原生下拉弹层的依赖，改为独立候选面板；点击下拉箭头和键盘输入使用同一套检索逻辑。
- 独立候选面板最多即时展示 100 个匹配项，支持包含式搜索、方向键定位、回车或鼠标确认、Esc 关闭。
- 悬浮窗底部按钮改为圆角彩色快捷按钮，启动、停止、取料、停靠使用不同的状态色和符号，悬停时高亮。
- 悬浮窗加入模态排除，即使主软件显示模态报错对话框，悬浮窗仍可置顶、点击和确认警告。
- 错误来源扩展为 MessageBoxes、直接 JOptionPane 错误窗口、标题包含错误/异常/失败/警告的对话框，以及未处理线程异常。
- 当 OpenPnP 主窗口位于前台时，悬浮窗自动隐藏摄像头画面，只保留标题栏和快捷按钮；主窗口失去前台或发生错误时恢复完整监控画面。
